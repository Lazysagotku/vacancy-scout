# Факты для сопроводительных писем

Единственный источник, из которого пишутся письма. Всё, чего здесь нет, в письмо не попадает.
Всё, что здесь есть, - проверено с Иваном. Правки - только через него.

## Кто

Иван Архипов, Москва. Семь лет в корпоративных системах финансового и государственного сектора.
Всю карьеру одно и то же по сути: разбирает проблему от заявки пользователя до кода, который закрывает её насовсем.
Английский: читает документацию свободно, речь понимает, устно отвечает с трудом.

## Направление с сентября 2026

Инфраструктура и эксплуатация: мониторинг, инциденты, автоматизация рутины, Linux, базы.

## Место 1. Мосгоргеотрест, июнь 2019 - март 2025, почти шесть лет

Государственная структура, работа с застройщиками и проектными организациями.
Внутренний веб-ресурс на Angular и TypeScript поверх PostgreSQL (частично Oracle), REST и SOAP, 15-20 бизнес-процессов.

- Поддержка на всех линиях: принимал и распределял заявки, консультировал пользователей напрямую (непрофильные сотрудники - объяснять на их языке), расследовал инциденты и сам закрывал.
- Построил собственную тикет-систему, после которой отдельная первая линия стала не нужна. Кадровая система с разграничением доступа по группам.
- Python: автоматизировал отчётность по расчёту аэротерриторий - сначала выгрузку, потом конструктор отчётов, которым руководство пользовалось само.
- Электронный секретарь на React и Python: многопоточные сессии, мониторинг через Selenoid, отчёты в Telegram-бот.
- Релизы через Jenkins: ID сборки от разработчиков, бэкап старой версии, загрузка новой, проверка через Postman и SQL-запросы.
- Мониторинг серверов в Zabbix, затем переход на Grafana. Отслеживал нагрузку серверов под окна бэкапов. Настраивал хосты, триггеры, графики, переносил дашборды.
- Диагностика: логи через WinSCP и SSH, Postman до Collection Runner (массовые запросы по списку ID), Swagger. Кейс: HTTP 418 в Postman оказывался Broken Pipe в логах Cassandra.
- Подготовка шагов воспроизведения ошибок для разработчиков на аутсорсе.
- IBM FileNet: контроль версий документов.
- Docker: все проекты в контейнерах - образы, старт, стоп, рестарт при обновлениях.
- MongoDB на федеральном проекте с данными по всей стране, выбрана под масштаб.

## Место 3. ТРИНФИКО, апрель 2025 - июнь 2026, финансовая структура

Разработчик и специалист третьей линии. Внутреннее ПО для финансовых процессов: учётные балансы, платежи, проводки.

- Backend на C#: основной объём - пошаговый дебаг и анализ причин ошибок по заявкам пользователей, без документации. Исправление.
- Хранимые процедуры на PostgreSQL и MS SQL, замена громоздких легаси-процедур на компактные и быстрые, сопоставление данных при миграции на новые структуры.
- TimeReportV3, собственный инструмент учёта заявок: двойная интеграция с тикет-системой и Jira через Dapper, выгрузка KPI в Excel с асинхронной обработкой, push-уведомления о нераспределённых задачах.
- Перенос заявок из внутренней тикет-системы в Jira на Python: цепочка из шести шагов с проверочным буфером, защита от дублей. В проде больше года, вся группа поддержки. Руководство импортировало задачи само, без обращения к Ивану.
- Jira: участвовал во внедрении, потом администрировал - проекты, права, учёт времени, Kanban, экспорт для аналитиков.
- Интеграции с внешними ресурсами: сайтмапы клиентов и биржи переросли в вебхуки; bash-скрипт с циклом проверки всех сайтмапов, wget с user-agent, email-алерты при несостыковках.
- RabbitMQ подключён через PIX Robotics для отслеживания сессий; Kafka - для баг-трекинга личного кабинета брокеров и клиентов (портфели, вводы и выводы, вход через Госуслуги).
- Отчётность: отдельный бэкенд, шаблоны отчётов через Visual Studio.
- Третья линия: консультировал бизнес-подразделения, помогал первой и второй линии по сложным обращениям, передавал знания.
- Сверка балансов, платежей и проводок между системой и выгрузками: суммы обязаны сходиться, расхождение - инцидент.

## Собственный стенд, сентябрь 2026

Облачный сервер на Ubuntu 24.04 (Timeweb), поднимает слоями своими руками по собственному роадмапу.

Сделано (можно писать в прошедшем времени):
- Вход по SSH-ключам, отдельный пользователь с sudo.
- Разобрал реальный сетевой инцидент: SSH не проходил снаружи, через tcpdump увидел SYN-ACK без ответа клиента, проверил доступность с 13 точек мира, доказал провайдеру проблему на его стороне, сменил адрес.

Впереди (только «сейчас поднимаю», никогда «поднял»):
- ufw, Docker, nginx с сертификатом, CI/CD, Prometheus с Grafana и Alertmanager, PostgreSQL в эксплуатации, k3s.

## ИИ-инструменты

Работает с ними как с рабочим окружением: собственная конфигурация Claude Code, MCP-серверы к базам и сервисам, автоматизация рутины через агентов.
Через это собрал себе трекер откликов и разведчик вакансий и эксплуатирует их на сервере.
**Код этих сервисов писал Claude, а не Иван.** В письме это звучит только как «собрал через Claude Code и эксплуатирую», никогда как «написал» или «разработал».
Проверяет результат ИИ как чужой код на ревью: читает, запускает, ломает на граничных случаях.

## Чего нет и как об этом говорить

Одной строкой, без «к сожалению», сразу с тем, что делается вместо.
- Kubernetes в проде: нет. «Разворачиваю на своём стенде через k3s.»
- ELK, Kibana, Opensearch: нет. «Поиск по логам делал напрямую - grep, journalctl, фильтры в Grafana.»
- Ansible, Terraform: нет.
- Informatica, NiFi, Airflow в проде: нет. «Airflow разворачивал дома, задачи ETL решал скриптами.»
- Astra Linux, отечественные СУБД: нет. «Принципы те же, что у Ubuntu и PostgreSQL.»
- Английский устно: с трудом. «Документацию читаю свободно, переписка без проблем, устная речь потребует времени.»
- Опыт руководства: нет.
- Kubernetes, микросервисы, Go, Java, 1С, обучение моделей: не в опыте.

## Что запрещено писать

- «Не X, а Y», «это не просто X, это Y» - только X.
- Длинное тире. Только дефис.
- Самоуничижение: «буду осваивать с нуля», «понимаю, что это не заменяет опыта», «к сожалению».
- Приписывать трекер и разведчик в собственную разработку.
- Markdown-разметка, звёздочки, списки через дефис: hh это не показывает.
- Повторять одну мысль дважды разными словами.
