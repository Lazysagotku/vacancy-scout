# Разведчик вакансий

Локальный сервис Ивана: собирает вакансии hh через Playwright, сохраняет их в SQLite, разбирает требования, оценивает совпадение с профилем и готовит сопроводительные письма. Веб-интерфейс работает на порту 8100. Секреты и профиль браузера хранятся вне Git.

## Текущий режим

Цикл сбора идёт по кругу каждые три часа и выполняет шесть шагов подряд: сбор
вакансий, перепроверка живости, письма и мнения, проверка сессии hh, разведка
форм отклика, отправка откликов, чтение исходов.

- Поиск использует сохранённые ссылки и встроенные запросы. Отказ одной ссылки
  не прерывает остальные.
- Вкладка «Рекомендовано» показывает короткую подборку с долями Python 60%,
  сопровождение 30%, C# 10%. Вакансии C# с требованием опыта вне 1-3 лет
  отсекаются.
- Письма пишет Claude через CLI, отдельным процессом без инструментов и без
  доступа к настройкам. Факты берутся только из `scout/facts/`. Ответ модели
  проходит механическую проверку: длина, обязательные начало и концовка,
  запрещённые обороты, отсутствие разметки и дословное совпадение зарплатной
  строки. Не прошедший ответ письмом не считается.
- Перепроверка живости открывает страницы разобранных вакансий и помечает
  ушедшие в архив. Сначала проверяются карточки короткой выдачи. Разобранная
  карточка старше окна выдачи закрывается по возрасту: на 120 проверках 82
  оказались в архиве, обходить такой хвост браузером дороже, чем он стоит.
- Отклик уходит сам при трёх условиях: балл выше 60, мнение модели
  «Рекомендую» или «Под вопросом +», ни одного блокера в `application_plan`.
  Суточный лимит 50, пауза между отправками 20-55 секунд со случайным
  разбросом.
- Письмо обязательно. Если поле сопроводительного на форме не найдено,
  отправка обрывается: голый отклик от имени человека хуже неотправленного.
- Вопрос работодателя без заранее известного ответа останавливает отклик.
  Известные ответы берутся из политики: зарплата по приложенному резюме,
  ссылка на портфолио. Собственный виджет hh «Задайте вопрос работодателю»
  вопросом не считается.
- Сессия hh живёт несколько часов и умирает молча. Цикл проверяет её перед
  разведкой форм и при потере присылает снимок экрана в личный чат Telegram.
  Ответ из одних цифр считается кодом подтверждения, любой другой текст -
  разгадкой картинки. Капчу разгадывает человек, сервис только передаёт
  снимок и вводит присланное.
- `scout/learning.py` читает страницу откликов hh и проставляет каждому
  отправленному исход: приглашение, отказ, просмотрен, молчание. Отчёт
  считает долю ответов по баллу, мнению, треку, резюме, длине письма и
  рейтингу работодателя. Различия называются только на группах от восьми
  откликов и при разбросе от 15 процентных пунктов.
- Живых откликов на момент написания отправлено ноль: цепочка собрана и
  проверена тестами, но первая живая пачка ещё не уходила.

### Выключатели

| Настройка | Что делает |
|---|---|
| `enabled` | цикл сбора |
| `auto_apply` | круг откликов и разведка форм внутри цикла |
| `live_apply` | живая отправка; без неё круг идёт вхолостую |
| `close_stale` | закрытие хвоста базы по возрасту |
| `recheck_limit` | сколько карточек перепроверять за заход, 0 выключает |

## Запуск и защита

Штатный запуск идёт через `run/_launcher.py scout` из корня общего проекта. Он загружает `vacancy-scout/.env`. При запуске вручную требуется передать `APP_USER` и `APP_PASSWORD` через окружение. Без `APP_PASSWORD` сервис возвращает 503. Пароль требуется и при обращении с localhost: туннель Cloudflare подключается к локальному порту.

```powershell
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m uvicorn scout.app:app --host 127.0.0.1 --port 8100
```

`APP_PASSWORD`, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` хранить только в локальном `.env`, который исключён из Git. Для привязки chat id требуется отдельная проверка владения чатом. Не помещать коды входа hh и скриншоты в журнал или базу.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

132 теста, сеть и браузер в них не участвуют: страницы hh подменяются, решения проверяются на данных. Живой сбор и живая отправка тестами не покрыты - для них нужны действующая сессия, актуальные резюме и работающая форма на стороне hh.

Отправка идёт через браузер от имени человека. Официальный API hh с OAuth зарегистрированного приложения рассматривался и не настроен; тесты работодателя API может не принимать, поэтому они остаются для ручного прохождения.

## Где что находится

- `scout/collector.py` - сбор через браузер и чтение вакансий.
- `scout/runner.py`, `scout/search_sources.py` - расписание и источники поиска.
- `scout/store.py` - SQLite и состояние находок.
- `scout/scoring.py`, `scout/profile.py`, `scout/policy.py` - оценка, профиль и правила выдачи.
- `scout/analysis.py`, `scout/writer.py`, `scout/letter.py` - разбор и письма.
- `scout/response_form.py` - чтение формы отклика: вопросы, резюме, поле письма.
- `scout/application_plan.py` - ворота отправки: порог, свежесть, мнение, письмо, форма.
- `scout/apply.py` - заполнение формы и отправка, суточный лимит, восстановление сессии.
- `scout/recheck.py` - перепроверка живости и закрытие хвоста по возрасту.
- `scout/hh_login.py` - вход в hh руками человека через Telegram.
- `scout/learning.py` - исходы откликов и разбор того, что сработало.
- `scout/telegram_bot.py`, `scout/telegram_worker.py` - Bot API и команды привязанного личного чата.
- `scout/app.py`, `templates/index.html` - API и интерфейс.

План следующих шагов и риски находятся в `tasks/plan.md`.
