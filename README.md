# Разведчик вакансий

Локальный сервис Ивана: собирает вакансии hh через Playwright, сохраняет их в SQLite, разбирает требования, оценивает совпадение с профилем и готовит сопроводительные письма. Веб-интерфейс работает на порту 8100. Секреты и профиль браузера хранятся вне Git.

## Текущий режим

- Поиск использует сохранённые ссылки и шесть встроенных запросов. Отказ одной ссылки не прерывает остальные. URL встроенных запросов ещё требует живой проверки на hh.
- Вкладка «Рекомендовано» показывает свежую короткую подборку Python 60%, сопровождение 30%, C# 10%. Вакансии C# с требованиями к опыту вне 1-3 лет отсекаются.
- Сбор вакансий и разбор страниц не запускают Claude. Письма готовятся отдельной фазой через `POST /api/letters/prepare?limit=10` или команду боту `/prepare`, когда ИИ доступен через VPN. Очередь ограничена вакансиями не старше 72 часов. Сервис не переключает VPN.
- Письма Claude получают согласованное ожидание по доходу: Python 170 000-200 000, C# 150 000-200 000, сопровождение 200 000 рублей на руки. Письма длиннее 190 слов, с нарушенной структурой, разметкой, длинным тире и запрещёнными оборотами отклоняются. При недоступности Claude остаётся шаблонный черновик, который не проходит в dry-run отправки.
- `GET /api/applications/preview` показывает dry-run будущей отправки и причины блокировки. Отклики он не отправляет.
- Приватный Telegram-бот принимает `/start`, `/status`, `/preview`, `/prepare`, `/questions` только из привязанного личного чата. `/questions` показывает свежие анкеты и консервативные черновики ответов. Дополнительные вопросы и тесты остаются для ручного прохождения. Передача скриншотов/кодов для входа в hh и отправка откликов пока не подключены. Реальные отклики не тестировались.
- Автоматическое открытие форм отклика при сборе отключено: интерфейс hh может измениться, а нажатие на кнопку имеет внешний эффект. Ранее сохранённые формы доступны для просмотра.

## Запуск и защита

Штатный запуск идёт через `run/_launcher.py scout` из корня общего проекта. Он загружает `vacancy-scout/.env`. При запуске вручную требуется передать `APP_USER` и `APP_PASSWORD` через окружение. Без `APP_PASSWORD` сервис возвращает 503. Пароль требуется и при обращении с localhost: туннель Cloudflare подключается к локальному порту.

```powershell
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m uvicorn scout.app:app --host 127.0.0.1 --port 8100
```

`APP_PASSWORD`, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` хранить только в локальном `.env`, который исключён из Git. Для привязки chat id требуется отдельная проверка владения чатом. Не помещать коды входа hh и скриншоты в журнал или базу.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

Сбор с hh и отправка откликов в тесты не входят. Для них нужны отдельная проверка живой сессии, актуальных резюме, формы отклика и ограничений hh. Для живой отправки рассматривается официальный API hh с OAuth зарегистрированного приложения; соответствующие токены сейчас не настроены. Формы с тестами API может не принимать, поэтому они требуют ручного прохождения.

## Где что находится

- `scout/collector.py` - сбор через браузер и чтение вакансий.
- `scout/runner.py`, `scout/search_sources.py` - расписание и источники поиска.
- `scout/store.py` - SQLite и состояние находок.
- `scout/scoring.py`, `scout/profile.py`, `scout/policy.py` - оценка, профиль и правила выдачи.
- `scout/analysis.py`, `scout/writer.py`, `scout/letter.py` - разбор и письма.
- `scout/response_form.py` - чтение вопросов формы без отправки.
- `scout/application_plan.py` - проверка кандидатов для будущей отправки, только dry-run.
- `scout/telegram_bot.py`, `scout/telegram_worker.py` - Bot API и команды привязанного личного чата.
- `scout/app.py`, `templates/index.html` - API и интерфейс.

План следующих шагов и риски находятся в `tasks/plan.md`.
