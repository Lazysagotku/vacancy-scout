# План доработки разведчика вакансий - 01.10.2026

## Цель

Получать релевантную выдачу с долями Python 60%, сопровождение L2/L3 30%, C# 10%; готовить правдивые письма и затем отправлять отклики автоматически без подтверждения каждого. Для C# подходят требования к опыту 1-3 года, для Python и сопровождения ограничение стажа не задаётся.

## Решения и границы

- Доли применяются к очереди показа и обработки. Если в одном треке нет качественных вакансий, место не заполняется нерелевантными.
- Поиск должен переживать отказ одной ссылки hh и явно показывать состояние источников. Старую базу не удалять.
- Внешняя отправка откликов будет отдельным этапом после тестов, проверки защиты сервиса и настройки учётных данных. Само изменение кода не должно отправлять реальные отклики.
- Авторизация через чат-бота требует отдельного канала и секретов вне Git. Коды и изображения капчи не хранить в БД и логах. Автоматического решения капчи нет.
- Канал выбран Иваном: новый приватный Telegram-бот. Токен и разрешённый chat id настроены локально в игнорируемом `.env`; код привязки подтверждён 01.10.
- Зарплатная формулировка: комфортные 200 000 рублей на руки во всех треках; Python 170 000-200 000, C# 150 000-200 000, сопровождение 200 000. Уточнение пользователя получено 01.10.

## Задачи

1. Зафиксировать тестами классификацию трека, C#-фильтр опыта и взвешенную выдачу. Проверка: `python -m unittest discover -s tests`.
2. Реализовать чистую политику отбора и применить её к выдаче/очереди, сохранив оригинальный скоринг и объяснения. Проверка: тесты и ручной просмотр API без сетевых запросов к hh.
3. Зафиксировать тестами формулировки зарплаты и доработать промпт письма без ложных фактов. Проверка: тесты + обзор 3 писем разных треков без отправки.
4. Восстановить несколько поисковых источников, раздельно по трекам, с диагностикой ошибок и ограничением нагрузки на hh. Проверка: тесты построения URL/планирования, затем ручной dry-run после входа.
5. Спроектировать отправку: eligibility, резюме, отсутствие дубля, архив/форма, журнал решения и результата, режим dry-run. Проверка: тесты на ошибках и повторном запуске.
6. Проверить внешнюю авторизацию сервиса через туннель; после этого подключать канал входа hh и отправку. Проверка: тест запросов извне и из localhost, без передачи кодов в логи.

## Состояние после локальных изменений

- Политика 60/30/10, ограничения C# и зарплатные строки реализованы и покрыты тестами.
- Встроенные поисковые запросы добавлены; сохранённый URL с 404 не прерывает обход. Фактические ответы hh ещё не проверены.
- Dry-run `/api/applications/preview` фильтрует старые, слабые и неполные карточки, дубли и анкеты с вопросами. В нём нет сетевой отправки.
- Локальный обход BasicAuth закрыт; без `APP_PASSWORD` сервис отвечает 503. Фактический туннель ещё требует проверки извне.
- Отправка откликов и Telegram-вход не реализованы. Перед включением нужны проверка официального API/OAuth, живой формы, резюме и защиты туннеля.

## Риски

- Сейчас единственная сохранённая ссылка hh возвращает 404, а действующего API-токена hh нет.
- В базе 7315 старых находок; автоматическая отправка по старому списку недопустима.
- В C#-резюме на hh ранее была указана другая зарплатная цифра; перед живой отправкой нужна сверка с актуальным резюме.
- Локальный bypass BasicAuth и cloudflared требуют проверки фактического адреса клиента за прокси.

## Продолжение 01.10 - VPN, анкеты и качество писем

### Архитектура

- Сбор hh и подготовка писем разделяются. Сбор и чтение формы работают в фазе доступности hh; генерация через Claude работает отдельной фазой при доступности ИИ. Ни одна фаза не переключает системный VPN.
- Бот получает команды для просмотра блокирующих вопросов и запуска подготовки писем. Сообщения принимаются только из уже привязанного личного чата.
- Известные ответы на вопросы строятся только из подтверждённых фактов и показываются как черновик. Неизвестные вопросы и тесты требуют ответа Ивана.
- Живая отправка остаётся выключенной. Целевой транспорт - официальный hh API с OAuth после регистрации приложения и проверки доступности метода для конкретного типа отклика. Анкеты, которые API не поддерживает, остаются ручными.
- Старый браузерный сборщик hh остаётся в проекте, но автоматическое открытие форм при проходе выключено. Условия hh ограничивают программную имитацию действий пользователя и скрапинг; перед масштабированием сбор тоже нужно перевести на официальный API.
